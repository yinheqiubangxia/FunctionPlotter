# Vela 快应用三件套 · 小米手环 / 红米手表

三个独立的 **Vela JS 快应用**（打包格式 `.rpk`），面向小米澎湃 OS（Vela）穿戴设备。
与仓库内 `rpk/`（Zepp OS 版）为不同平台，**不可混用**。

## 一、应用清单与功能定位

| 应用 | 目录 | 功能定位 | 核心交互 |
|---|---|---|---|
| **函数绘图器** | `plotter/` | 数学工具：输入 sin(x)/x^2+1 等表达式画曲线 | 自研函数软键盘、单指拖动平移、双指捏合缩放、浅/深主题切换 |
| **番茄钟** | `pomodoro/` | 效率工具：专注/休息循环计时 | 圆环进度、15/25/45 分钟切换、结束震动提醒、轮次统计 |
| **单位换算** | `converter/` | 生活工具：长度/重量/温度换算 | 数字键盘、点击循环切换单位、科学计数法兜底 |

三个应用均为**纯设备端**，不依赖网络与手机伴生服务。

## 三、兼容性处理方式

1. **运行时设备探测**（`src/common/device.js`，三应用共用同一模块）
   - `device.getInfoSync()` 读取型号与真实屏幕宽高；
   - 先按已知型号精确匹配，未命中再按分辨率区间归类（胶囊 / 矩形手环 / 矩形手表）；
   - 输出安全区 `safe`：胶囊屏弧形边缘上下内缩 10%、左右内缩 6%，可交互元素不放在弧边。
2. **布局策略**
   - `manifest.json` 中 `designWidth: 192`（胶囊屏基准），快应用框架按 DP 自动缩放；
   - 画布类（绘图器、番茄钟圆环）尺寸按设备实际像素/短边动态计算，不写死；
   - 窄胶囊屏用「点击循环切换」替代下拉列表/长列表（换算器单位选择）。
3. **性能约束**（手环算力弱，三应用统一遵守）
   - 绘图器采样点 ≤96、求值函数复用、16ms 节流重绘、渐近线断点；
   - 番茄钟每秒仅重绘一个圆环，无高频动画；
   - 无大数组、无位图缓存，内存占用保持最小。
4. **系统差异**
   - 全部使用快应用标准 API（`@system.device` / `@system.vibrator`），不依赖私有接口；
   - 温度换算等纯 JS 计算无平台依赖。

## 五、工具链与构建（已配置并验证）

**选型：开源工具链 + aiot-toolkit（无需 AIoT IDE）**，原因：构建 RPK 只需 npm 包
`aiot-toolkit`，命令行即可完成；IDE 仅在需要图形模拟器时才必要。

- 工具链位置：`E:\tools\xiaomi-band-development`（模拟器 gRPC 控制 / 真机部署脚本）
- 构建依赖：各应用目录 `npm install` 安装 `aiot-toolkit@2.0.5`（已装好）
- 本机环境：Node v22、ADB 36.0.2 均已就绪

构建命令（在各应用目录下执行）：

```bash
npm run build        # 如遇到删除 shim 报错，用 NODE_OPTIONS= npm run build
```

**三个应用均已实际构建成功**，产物（debug 签名）。`release/` 目录提供按设备系列命名的分发副本：

| 分发文件名 | 对应应用 | 大小 |
|---|---|---|
| `release/小米 Band.rpk` | 绘图器 plotter | ~24 KB |
| `release/小米 Band Pro.rpk` | 番茄钟 pomodoro | ~24 KB |
| `release/Redmi Watch.rpk` | 换算器 converter | ~20 KB |

真机安装（手机 ADB 连接 + 小米运动健康配对设备后）：

```bash
E:/tools/xiaomi-band-development/scripts/deploy.sh --project <应用目录> --no-build
```

> 注意：Windows 本环境下首次构建若报 `safe-delete` 错误，是终端注入的 NODE_OPTIONS
> 与构建工具清理临时目录冲突，加 `NODE_OPTIONS= ` 前缀即可（上文命令已处理）。
> RPK 已通过编译与打包验证；界面表现仍需真机/模拟器最终确认。
> 手环 11 / 10 Pro / Watch 6 分辨率为预估值，发布前以官方设备表为准。
