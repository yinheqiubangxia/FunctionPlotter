# 函数绘图器 · 小米手环 RPK 版

在手环上输入 `sin(x)`、`x^2+1` 等表达式，立刻画出曲线，支持拖拽平移、双指缩放查看不同区域。

> 本目录是独立的 **Zepp OS 手环小程序工程**（RPK），与仓库根目录的 Windows/Android 桌面版**共用同一套算法思路**，但运行时是纯 JavaScript（Zepp OS 的 JS 引擎），不复用 .NET/Kotlin 代码。

---

```
└─ app-side/
   └─ index.js              （可选）手机端设置页占位
```

## 二、关键实现思路

### 1. 绘图与渲染（性能核心）

- **采样点数量与屏幕宽度挂钩**：手环画布约 194px 宽，采样点上限 `MAX_SAMPLES = 96`，实际约 `widthPx × 0.5 ≈ 97` 点。96 段折线在手环上视觉已平滑，再密就是浪费算力。
- **渐近线断点**：逐点求值，遇到 `NaN/Infinity` 或相邻点 Y 跳变超过当前范围 `JUMP_RATIO=40` 倍时置 `break`，绘制时断线，`tan(x)`、`1/x` 不会再画出一条贯穿全屏的竖线。
- **Y 轴自适应用分位数**：取 5%~95% 分位数作为可视范围，单个尖峰不会把曲线压扁成一条直线。
- **增量 + 节流重绘**：`_scheduleRedraw` 用 16ms 节流合并连续触发（拖动/缩放/连续按键），避免每帧全量重画。全量重绘只做三件事：清屏 → 画网格轴 → 画曲线，drawLine 调用次数与采样点数同阶，无冗余。
- **复用求值函数**：表达式只在文本变化时 `compile` 一次，得到 `f(x)` 闭包后反复调用，不重复解析。

### 2. 手势（拖动 + 缩放）

- Zepp OS 的 canvas 通过 `addEventListener` 提供 `CLICK_DOWN / CLICK_UP / MOVE`，事件带 `x/y`，多点触控时带 `touches` 数组。
- **单指拖动**：`MOVE` 的像素位移 → 数据坐标位移（方向取反），直接平移视口。
- **双指缩放**：检测到 `touches.length >= 2`，计算两触点间距 `dist`，`scale = dist / lastDist`，以两触点中点为锚点缩放视口（锚点保持不动）。
- 手环没有内置 pinch API，这套逻辑完全自己算，兼容任意支持两点的触屏。

### 3. 输入模块（键盘选型）

**结论：不集成「喵喵键盘」，改为自研屏内软键盘。**

调研结论：
- 网上流传的「喵喵键盘」实际指向两个完全不同的东西：一个是 Android AOSP 输入法魔改版 **KittenBoard**（`nyancrimew/KittenBoard`），另一个是立创电赛的硬件 HID 键盘 **MeowKJ/BinaryKeyboard**。**两者都跑在手环 RPK 上不可行**——手环没有 Android IME 框架，也不会挂外置 HID 设备。
- Zepp OS **没有暴露系统级软键盘 API**，`hmUI` 也没有内置键盘 widget。

因此正确方案是**用 `hmUI.widget.BUTTON` 自绘屏内键盘**，并针对「函数表达式」场景优化布局（见 `shared/keyboard.js`）：
- 数字、运算符、括号、`.`、`x`、`^`、`π` 直接可用；
- `sin(` `cos(` `tan(` `√(` 做成单键，一键插入「函数名 + 左括号」，减少击键；
- `π` 一键插入 `pi`，避免记常量名。

### 4. 主题（HyperOS 柔光玻璃）

- 手环 canvas **无法做真正的 GPU blur**，因此「磨砂质感」用「半透明叠加层 + 低对比柔和色 + 大圆角（radius 12）」近似实现。
- 色板集中在 `shared/theme.js`，`LIGHT` / `DARK` 两套，默认深色（OLED 省电、更贴合澎湃深色观感）。
- 主色采用澎湃蓝 `#2F6BFF`（深色下提亮为 `#5B8CFF`）。

## 三、兼容性注意事项（小米手环 RPK / Zepp OS）

| 类别 | 注意点 |
|---|---|
| **屏幕基准** | 手环（bracelet）基准分辨率 **194×368**，非手表 480×480。所有布局用 `px()` 按 `designWidth=194` 缩放，切到不同型号手环自动适配。 |
| **API_LEVEL** | `CANVAS` 从 **API_LEVEL 3.0** 才提供（即 Zepp OS 3.x）。若目标设备是 Zepp OS 2.0 的旧手环，需回退到 `hmUI.widget.CANVAS`（v1.0 API）写法，或干脆放弃 canvas 用折线 widget 拼。请确认目标手环型号的系统版本。 |
| **模块导入** | Zepp OS 2.0+ 用 ESM（`import ... from '@zos/ui'`）；1.0 用全局 `hmUI`。本工程按 2.0/3.0 ESM 编写。 |
| **触控事件** | `MOVE` 事件在部分型号上频率较低，且**是否带 `touches` 数组因型号而异**，代码里做了单点/多点兼容回退。 |
| **双指缩放** | 无内置 API，靠两点间距自行计算；低端屏触摸采样率低，缩放可能略「跳」，已用 16ms 节流缓解。 |
| **性能** | JS 引擎算力弱（约手机 1/10 甚至更低），务必：采样点 ≤96、求值函数复用、重绘节流、避免 `setInterval` 高频重画。 |
| **内存** | 小程序运行内存有限，不要在页面里持有大数组/位图；本工程每帧只保留 ≤96 个采样点的临时数组。 |
| **文本渲染** | canvas `drawText` 与 `widget.TEXT` 的字体渲染有差异，刻度/标签用 `widget.TEXT` 更稳，canvas 上少画文字。 |
| **状态栏** | 方形/手环屏顶部有 64px 状态栏占位，布局时已从 `y=48px` 之后开始（`EXPR_H`）。 |

## 四、构建与预览

1. 安装 **Zeus CLI**（`npm i -g @zeppos/zeus`）与 Zepp OS 模拟器。
2. 在 `rpk/` 目录下执行 `zeus dev` 用模拟器预览。
3. 真机预览：`zeus preview`（需 Zepp App 绑定设备）。
4. 打包：`zeus build` 产出可提交到 Zepp 应用市场的包。

> 注意：本工程**尚未实际在模拟器/真机编译验证**。`app.json` 的 `appId` 需替换为你申请的真实 appId，`icon.png` 需替换为 80×80 的 PNG。建议先在模拟器跑通 `zeus dev`，再按官方文档提交审核。
